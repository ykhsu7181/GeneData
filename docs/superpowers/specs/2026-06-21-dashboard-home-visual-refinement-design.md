# Dashboard 首页第二轮视觉细化设计

## 背景

当前项目已经完成首页第一阶段改造：

- 后端已提供统一首页聚合接口 `GET /gd/api/warehouse/dashboard/`
- 前端已新增 `DashboardHomeView.vue` 和若干首页组件
- 默认入口已切换到顶部导航 + 首页门户入口

但当前首页仍存在两个问题：

1. 视觉上与目标图差距较大，仍偏“后台管理页”
2. 首页内容过长时，整页滚动体验不理想，影响浏览和导航

本轮目标是在不破坏现有业务页面、不引入旧 `GenomeFile` 逻辑、不重写首页数据链路的前提下，将首页细化为更接近目标图的门户型页面。

## 目标

本轮设计目标如下：

- 首页视觉尽量高还原目标图
- 首页恢复标准门户页的整页纵向滚动
- 顶部导航改为固定吸顶
- 首页使用现有或通用素材占位，不阻塞结构与样式升级
- 继续使用 `DataFile + FileRelation` 的新链路，不引入 `GenomeFile` 或 `organism` fallback
- 尽量复用现有首页聚合接口和现有数据，不新增复杂统计口径

## 非目标

本轮不做以下内容：

- 不修改数据库结构
- 不新增 migration
- 不恢复或依赖 `GenomeFile` / `organism` 旧逻辑
- 不重写现有业务详情页、分析页主体
- 不在前端自行重新计算首页统计总数
- 不强行把业务定义不稳定的数据包装成首页固定指标

## 设计原则

### 1. 首页统计只认统一后端口径

首页所有核心数字、卡片、图表、地图，统一来自后端聚合服务。前端只负责：

- 拉取首页接口
- 渲染卡片
- 渲染图表
- 渲染地图
- 做搜索跳转和交互反馈

前端不再对首页统计做二次拼装或重新汇总。

### 2. 视觉高还原优先，但不牺牲业务口径正确性

目标图可以作为视觉参考，但不能为了外观一致而硬套错误业务文案。

典型约束：

- 单物种卡片的指标要优先使用项目中真实、通用的统计项
- “XI 群分布”如果当前后端口径并不真正表示 XI 群，则不能强行按 XI 命名

### 3. 第二轮优先重做“看起来最不像目标图”的区域

本轮优先级：

1. 页面壳层与滚动
2. 顶部导航
3. Hero 首屏
4. 物种卡片区
5. 图表区容器样式与信息层级
6. 地图区容器与图例样式

## 方案选择

本轮采用“方案 B：首页视图重组，组件保留一部分、替换一部分”。

### 选择原因

- 比仅做样式微调更接近目标图
- 比完全推翻现有首页组件更稳
- 能保留当前首页 API 和已有路由接线
- 能把改动集中在首页壳层与首页专用组件，避免扩散到现有业务页

## 信息架构

首页结构调整为：

1. `TopNavBar`
2. `DashboardHero`
3. `SpeciesCardGrid`
4. `DistributionSection`
5. `GeoMapSection`
6. 页面底部留白或页脚占位

### 页面层级要求

- `TopNavBar` 固定吸顶
- `DashboardHero` 作为完整首屏区域
- Hero 以下内容使用统一内容宽度
- 所有首页区块按门户页节奏增加留白
- 首页使用整页滚动，不锁死内容高度

## 视觉设计

### 顶部导航

顶部导航采用深蓝色品牌条风格：

- 左侧展示系统中英文名称
- 中间展示主导航入口
- 右侧展示语言切换、当前用户、退出
- 当前路由使用胶囊式高亮
- 导航固定吸顶
- 页面滚动后增加轻微阴影和毛玻璃效果

### Hero 首屏

Hero 采用“大图背景 + 遮罩 + 大搜索框 + 热门标签”的结构：

- 背景使用农业/作物类通用素材占位
- 添加深色叠加层，保证文字可读性
- 主标题突出“基因数据仓库首页”
- 副标题强调“快速检索与浏览”
- 搜索框宽度明显大于普通业务表单
- 热门搜索标签以胶囊按钮形式展示

### 物种卡片区

物种卡片采用图片型门户卡片：

- 顶部为封面图
- 卡片主体为白底信息区
- 显示中文名与拉丁名
- 底部使用三项核心指标
- 卡片底边使用品牌色强调线
- Hover 时有轻微抬升和阴影变化

### 图表区

图表区采用左右并排双面板结构：

- 左侧：亚群分布
- 右侧：中性命名的群体分布模块

每个面板统一包含：

- 标题
- 辅助英文小标题
- 左侧总览卡
- 中部环图
- 右侧图例/排行列表
- 右上角视图切换按钮样式

### 地图区

地图区采用横向大卡片结构：

- 顶部标题区
- 中部地图
- 右侧或右下图例
- 缩放控件样式统一
- 使用现有地图数据与现有图表库能力

## 数据复用策略

### 可直接复用的数据

#### 1. 亚群分布

直接复用 `dashboard_service.py` 中 `_build_sub_population_distribution()` 的结果。

原因：

- 来源单一，直接来自 `Accession.sub_population`
- 与当前数据页筛选字段一致
- 空值处理已经统一为 `Unknown`

#### 2. 地理分布

直接复用 `dashboard_service.py` 中 `_build_geo_distribution()` 的结果，重点使用：

- `region`
- `latitude`
- `longitude`
- `accession_count`
- `sample_count`

说明：

- 地图点位和数量统计可以直接用于首页
- `dataset_count` 先不作为首页地图核心展示字段，以避免口径误解

### 需要调整文案或口径的数据

#### XI 群分布

当前 `dashboard_service.py` 中 `_build_xi_distribution()` 实际按 `Accession.genetic_stock_id` 分组，不应直接在首页固定命名为“XI 群分布”。

本轮策略：

- 保留右侧图表模块的位置与视觉结构
- 标题改为更中性的“群体分布”或“遗传分组”
- 若后续确认有稳定 XI 口径，再恢复为专题命名

## 交互设计

### 搜索

首页搜索仍沿用现有结构化跳转逻辑：

- 命中 accession：跳转 `accession-card`
- 命中物种：跳转 `data-overview`
- 命中亚群：跳转 `data-overview` 并带筛选参数
- 命中地理关键词：跳转地图页
- 命中特定模块关键词：跳转对应业务页

本轮只升级视觉和交互表现，不引入复杂全文检索结果页。

### 滚动

首页必须恢复整页纵向滚动：

- 不再锁定首页主容器高度
- 吸顶导航存在时，主内容留出安全顶距
- 页面滚动时导航视觉状态发生变化

### 加载态

首页采用分区骨架屏：

- Hero 直接显示，不做骨架
- 物种卡片使用卡片骨架
- 图表区使用面板级骨架
- 地图区使用地图占位骨架

### 错误态

首页错误态统一为温和的页面内提示，不采用多个接口分别抛错。

## 组件边界

### `App.vue`

负责全局壳层：

- 吸顶导航容器
- 首页与业务页的布局差异
- 页面滚动容器控制

### `TopNavBar.vue`

负责顶部导航的展示与交互：

- 品牌
- 菜单高亮
- 用户区
- 滚动态样式变化

### `DashboardHero.vue`

负责首页首屏：

- 大图背景
- 标题与副标题
- 搜索框
- 热门标签
- 关键摘要数字展示

### `SpeciesCardGrid.vue`

负责首页物种卡片展示：

- 封面图
- 名称区
- 核心指标区
- 点击跳转

### `DistributionPanel.vue`

负责首页双图表面板的统一壳层：

- 标题区
- 统计总览
- 图例列表
- 图表展示区域

### `GeoMapPanel.vue`

负责首页地图区：

- 地图渲染
- 点位展示
- 图例与交互跳转

## 数据流

首页数据流保持简单：

1. `DashboardHomeView` 请求 `/gd/api/warehouse/dashboard/`
2. 后端统一返回：
   - summary
   - species_cards
   - sub_population_distribution
   - xi_distribution
   - dataset_type_summary
   - file_role_summary
   - geo_distribution
   - hot_keywords
3. 前端按模块分发数据给展示组件
4. 用户触发搜索或点击卡片后，前端进行结构化路由跳转

## 风险与处理

### 风险 1：首页统计口径不一致

处理：

- 所有首页统计只认后端统一聚合结果
- 前端不自己拼总数

### 风险 2：XI 模块名称与真实口径不一致

处理：

- 第二轮先改为中性命名
- 不强行保留“XI 群分布”标题

### 风险 3：首页过长后导航体验差

处理：

- 页面改为整页滚动
- 导航改为固定吸顶

### 风险 4：视觉重做波及旧业务页

处理：

- 把改动集中在首页视图与首页专用组件
- 业务页只复用全局顶部导航和基础壳层

## 测试与验收

本轮实施后，至少需要验证：

1. 首页能够整页纵向滚动
2. 顶部导航固定吸顶
3. 首页视觉明显接近目标图
4. 亚群分布正常展示
5. 地理分布图正常展示
6. 右侧群体分布模块不使用错误业务命名
7. 首页搜索跳转仍正常
8. 原有业务页路由不报错
9. 不引入 `/genome-files/` 下载链接
10. 不修改数据库，不产生 migration

## 分阶段实施建议

### 第二轮实施范围

本次实施只覆盖：

- 页面壳层与滚动修复
- 顶部导航视觉升级
- Hero 视觉升级
- 物种卡片视觉升级
- 图表与地图区容器升级
- 加载态与错误态统一

### 暂缓项

以下内容暂不纳入第二轮：

- 全量替换首页图片素材为正式资产
- 新增全文检索结果页
- 重新定义 XI 专题口径
- 新增更复杂的首页聚合字段

## 结论

本轮首页视觉细化采用“高还原目标图，但坚持统一统计口径”的策略推进。

在实现上，首页继续以 `/gd/api/warehouse/dashboard/` 作为唯一首页数据入口，前端重点改造页面壳层、导航、Hero、卡片与图表地图容器；其中亚群分布和地理分布直接复用当前数据，右侧 XI 模块改为中性分组模块，避免业务含义失真。
