# GeneData ADR-005 阶段二 P0 调用面处置矩阵

## 1. 基线与用途

本矩阵基于 commit `1de5530a3328b4248512a09b24241c41c87024a6` 重新搜索当前 HEAD，冻结旧 `Dataset`、`FileRelation`、旧专业实体和 `DataAccessToken` 的运行入口去向。它只决定入口由哪个后续 Gate 处理，不授权删除旧表、改变旧 API 契约、生产部署或旧数据迁移。

核对结果：

- `resolve_data_asset_file_access()` 除单元测试外没有 service、view、command 或 URL 调用者；
- 当前新仓授权 service 仍调用旧 `resolve_datafile_access()`，因此间接依赖 `Dataset`、`FileRelation` 和 `DataAccessToken`；
- 旧文件 API、JBrowse、索引、查询、导入和前端仍是相互独立的遗留运行路径；
- 历史 migration 永久保留，不属于活动调用切换范围。

## 2. 处置含义

| 处置 | 含义 |
| --- | --- |
| `switch-phase2` | 阶段二必须切换为新核心；切换后该能力不得读取旧关系或 fallback |
| `legacy-until-phase3` | 阶段二不改其旧语义，阶段三删除或停用 |
| `new-api-phase4` | 阶段二只准备内部 service，不创建正式用户入口；阶段四实现新 API/前端 |
| `archive-only` | 只保留历史审计、迁移或恢复证据，不进入新仓运行路径 |

## 3. 能力与运行入口矩阵

## 4. Management command 去向

| 类别 | 代表入口 | 处置 |
| --- | --- | --- |
| 阶段二重构保留 | `build_fasta_indexes`、`build_annotation_feature_indexes`、`build_jbrowse_indexes`、`backfill_jbrowse_refname_aliases` | Gate C 改为新资产能力；不得保留 FileRelation fallback |
| 阶段二重构保留 | `import_data_batch` | Gate D 原地改为唯一新仓写入编排 |
| 阶段三删除/停用 | `import_dataset_*`、`publish_external_datasets`、`import_*_manifest` 旧专业入口、`bind_manual_files`、`migrate_placeholder_hierarchy`、`cleanup_placeholder_hierarchy`、`reconcile_assembly_annotation_context` | `legacy-until-phase3` |
| 历史审计 | `audit_dataset_*`、`audit_datafile_asset_mapping_readiness`、`audit_file_relations` | `archive-only`；证据保留，活动命令后续单独退出 |
| 旧 Token 运维 | `issue_data_access_token`、`list_data_access_tokens`、`revoke_data_access_token` | `legacy-until-phase3`；等待独立 Token 决策 |

未在表中点名但直接读取 Dataset、FileRelation 或旧专业实体的命令，默认归入 `legacy-until-phase3`，除非 Gate C/D 的实施 diff 明确证明其通用能力被原地重构且不存在 fallback。

## 5. Gate A 冻结范围

Gate A 只允许修改：

- `django2/files/services/data_asset_access_service.py`；
- 对应的新仓授权单元测试；
- 本矩阵、阶段二方案、ADR-005 批准记录和活动文档索引。

Gate A 不允许修改 model、migration、旧 `datafile_access_service.py`、API、URL、serializer、management command、JBrowse、前端或生产配置。

Gate A 完成后必须证明：

1. 新授权 service 不导入或查询 Dataset、FileRelation、旧专业实体、DataAccessToken 或 `Project.owner`；
2. owner、manager、contributor、viewer、创建者、非成员、匿名和停用用户矩阵通过；
3. 可见资产 queryset 与单对象决策一致；
4. Context 完整读取和公开 metadata 投影边界通过；
5. `uses_reference` 每次使用重新授权两端，跨 Project 目标必须仍为 `released + public`；
6. 资产成员文件授权只确认可见资产和明确 membership，不读取旧文件授权；物理状态与受控路径留给 Gate B；
7. 不可见与不存在的对外映射继续留给未来 API 边界，Gate A 只返回稳定领域 reason code。

## 6. P0 结论

当前 HEAD 没有发现必须阻止 Gate A 的未知新仓运行调用者。Gate A 可以原地替换尚未接入正式入口的 `data_asset_access_service.py`，同时保持所有旧入口原样隔离。完成 Gate A 不等于文件交付、JBrowse、导入、查询、API、前端或生产切换完成。
