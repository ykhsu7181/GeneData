# GeneData ADR-004 G4 代码适用性与调用面审计

## 1. 审计目的与状态

本报告执行 ADR-004 的 G4 本地代码审计，回答：

1. 哪些代码可以作为新仓空库的通用基础继续使用；
2. 哪些代码只服务旧数据迁移或旧业务体系；
3. 哪些当前功能仍依赖 `Dataset`、`DatasetAccession`、`FileRelation` 和旧专业实体；
4. 删除旧表之前必须先替换哪些模型、权限、API、前端和测试；
5. 最终正向删除 migration 应按什么边界实施。

本报告只记录当前代码事实和删除前置条件，不修改 model、migration、API、前端或生产环境，也不批准 `ContextEntity` 等新结构。

**审计交付物状态：本地完成。** ADR-004 的 Gate 顺序尚未整体完成：G2 的数据库隔离恢复验证已延期，G3 尚未执行，因此不能把本报告描述为 G2、G3 或整个 G4 阶段均已验收完成。

## 2. 审计范围与方法

审计范围：

- `django2/files/models.py`；
- `django2/files/migrations/`；
- 后端 service、management command、API、serializer、view 和 URL；
- `vue_project/src/` 中的 Dataset 展示与筛选；
- 后端和前端相关测试；
- ADR-004、活动文档索引和仓库级规则。

方法：

- 搜索大小写不敏感的 `dataset` 及 `FileRelation` 调用；
- 搜索 `DataAsset`、`AssetFileMembership` 和四类显式专业上下文关系；
- 检查模型外键、权限继承、API 输出、前端展示和测试契约；
- 运行当前 DataAsset 最小相关测试、Django 系统检查、migration 漂移检查和前端测试。

本报告没有访问生产数据库或生产文件，没有根据旧数据内容推断新仓模型。

## 3. 当前实现事实

### 3.1 DataAsset 已在开发代码中实现

当前开发代码已经存在：

- `DataAsset`；
- `AssetFileMembership`；
- `DataAssetAccession`；
- `DataAssetSample`；
- `DataAssetAssembly`；
- `DataAssetAnnotation`；
- migration `0026_auto_20261118_1523.py` 和 `0027_dataasset_context_links.py`；
- Profile 注册表及校验 service；
- 唯一 `create_data_asset` 创建 service；
- DataAsset 与成员文件组合权限判断 service；
- 对应模型、注册表、创建、权限和 T4 dry-run 测试。

这些事实只证明开发实现存在并通过本地测试，不证明已经部署生产，也不证明其专业上下文设计仍适合 ADR-004 后的新仓。

仓库级调用搜索进一步确认，`create_data_asset()` 和 `resolve_data_asset_file_access()` 当前都没有测试以外的调用者：没有 API、management command、view 或前端流程通过这两个 service 创建或读取 DataAsset。因此当前状态应准确描述为“开发模型与最小 service 基础已经存在”，不能描述为“新仓业务链路已经接通”。

仓库根 `AGENTS.md` 第 48 行仍写着“当前 `DataAsset` 尚未实现”，与当前 model、migration 和测试事实冲突。该事实描述需要在后续独立治理修改中更正；本次审计不直接修改仓库级规则。

### 3.2 旧活动结构仍是大量功能的事实来源

当前模型仍包含：

- `Dataset`；
- `DatasetAccession`；
- `DataFile.dataset` 可空外键；
- `FileRelation` 的字符串 `related_type + related_id` 多态关系；
- Accession、Sample、Assembly、Annotation 等专业实体。

`FileRelation` 的 `RELATED_TYPE_CHOICES` 同时包含 accession、assembly、annotation、dataset、sample 和若干分析类型。它没有到这些业务对象的数据库外键，但当前 JBrowse、数据总览、原始数据、外部接口、索引构建和多类导入命令仍依赖它。

按大小写不敏感的 `dataset` 或 `FileRelation` 搜索，得到以下待人工分类的文本命中文件：

- 58 个后端运行时代码文件；
- 其中 26 个 management command、21 个 service，以及 model、serializer、URL 和 view/API 文件；
- 56 个后端测试文件；
- 6 个前端源文件。

这些数量是调用面候选，不等同于 58 个文件都存在相同程度的运行时依赖。逐文件人工处置结论见 `docs/audits/GeneData_ADR004_G4调用面处置清单_20261126.md`。删除旧表不是单个 migration 任务，而是模型、权限、查询、接口、前端和测试契约的分阶段替换。

## 4. 关键阻断项

### 4.1 DataFile 权限仍依赖 Dataset

`DataFile.access_level` 默认值为 `inherited`。当前 `datafile_access_service` 同时读取：

- `DataFile.dataset_id`；
- `FileRelation(related_type="dataset")`；
- `Dataset.status` 和 `Dataset.visibility`。

当文件没有 Dataset 权限来源时，该 service 按安全失败原则返回 private。该行为是安全的，但意味着直接删除 Dataset 后，大量文件将无法按新仓资产权限正常访问。

`data_asset_access_service` 虽然先检查 DataAsset 发布状态、可见性和文件成员关系，最终仍调用旧 `resolve_datafile_access`。因此当前 DataAsset 权限链并未真正脱离 Dataset。

**删除前置条件：** 先批准并实现以 DataAsset、Project、成员文件和明确文件级限制为基础的唯一权限决策路径，逐节点保持 fail-closed，并替换所有外部文件访问调用。

### 4.2 DataAsset service 尚未接入运行入口

当前创建和访问 service 只有单元测试调用，没有 API、命令或页面调用。这一边界有两个后果：

- 现有测试证明 service 内部约束成立，不证明用户能够完成一次新仓资产创建、查询或文件访问；
- 后续应先在 G6 建立最小受控入口并复用唯一 service，不能另写一套 API 写入逻辑。

**验收前置条件：** G5 只验证空库最终 schema 和应用能够启动；G6 再验证从零创建账号、Project、Profile、DataAsset 和文件成员的最小后端流程。两者均不能根据 service 文件存在直接判定完成。

### 4.3 Project 当前不是已实现的权限边界

当前 `Project` 只有字符串 `owner`、名称和状态等字段，没有到 Django 用户的 owner 外键，也没有成员、角色或授权关系。`resolve_data_asset_file_access()` 只检查 `asset.project_id` 是否存在，不检查请求用户是否属于 Project；它当前主要处理 `DataAccessToken` 的 scope 和 access tier。

因此“Project 是治理和权限边界”目前是目标设计，不是已实现事实。仅移除 Dataset 权限继承会留下一个没有 Project 成员授权依据的访问链。

**删除前置条件：** ADR-005 必须明确 Project 成员与角色、资产可见性、文件级限制、DataAccessToken 与用户授权的组合规则，以及每个返回节点的重新授权要求。对应 model、constraint 和测试完成前，不删除 Dataset 权限来源。

### 4.4 DataAsset 创建 service 仍固定依赖四类专业关系

`create_data_asset` 当前接收：

- `accession_links`；
- `sample_links`；
- `assembly_links`；
- `annotation_links`。

它直接创建四张显式中间关系表，Profile 注册表也固定校验 accession、sample、assembly、annotation 四类上下文数量。这与当前讨论中的通用 `ContextEntity` 候选方案存在方向冲突。

**删除前置条件：** ADR-005 必须先决定专业实体、通用上下文、外部编号和资产关系的最终边界，再修改创建 service 和注册表。不得先删除旧关系表再用无约束 metadata 临时代替。

### 4.5 外部 API 仍公开 Dataset 契约

当前外部接口包含：

- `/gd/api/v1/datasets/{dataset}/manifest/`；
- `/gd/api/v1/datasets/{dataset}/manifest.tsv`；
- 文件 metadata 响应中的 `dataset` 字段；
- accession 文件筛选中的 `dataset` 参数；
- `dataset:manifest` token scope；
- OpenAPI 中的 DatasetManifest schema。

这些接口依赖 `Dataset`、`DatasetAccession`、`DataFile.dataset` 和 `FileRelation`。直接删表会破坏已存在的 API 和 token 权限契约。

**删除前置条件：** G7 前明确这些接口是退役、升级为 asset manifest，还是通过新的 API 版本替代；不得在原路径下静默改变标识含义。

### 4.6 Data Overview 和 Accession 页面仍展示 Dataset

当前前端仍包含：

- Data Overview 的 Dataset 筛选项、可选列和详情字段；
- Accession 详情的 Datasets 标签页；
- 首页 annotation datasets 文案及兼容字段；
- 对应中英文文案和源代码行为测试。

后端 `data_overview_v2_service` 同时从 `DataFile.dataset`、`DatasetAccession` 和 `FileRelation` 聚合文件、上下文和筛选项。

**删除前置条件：** 新资产查询和详情 API 稳定后，前端一次性切换为 DataAsset、Profile、上下文和文件成员语义，同时删除旧 Dataset 展示和测试；不保留双读页面。

### 4.7 JBrowse、AnnotationFeature 和专业详情仍依赖旧关系

当前 JBrowse 与专业详情通过 `FileRelation` 按 assembly、annotation 和文件角色选择 FASTA、GFF、索引及派生配置。`AnnotationFeatureIndex` 直接关联旧 `Annotation` 和一个 `DataFile`。

**删除前置条件：** ADR-005 决定 Assembly、Annotation 是否作为 DataAsset，以及 `AnnotationFeatureIndex` 关联 Annotation DataAsset、核心 DataFile 或二者的方式；之后才能替换 JBrowse 和索引服务。

## 5. 代码适用性分类

### 5.1 可作为空仓基础保留

以下能力方向与空仓一致，可以保留，但仍须通过 G5 空数据库验证：

| 能力 | 当前实现 | 结论 |
| --- | --- | --- |
| 项目容器候选 | `Project` | 保留名称和归属概念；当前没有成员/角色授权模型，不能称为已实现的权限边界 |
| 物理文件事实 | `DataFile` | 保留；删除 `dataset` 外键并重构权限后才独立 |
| 科研数据统一身份 | `DataAsset` | 保留 |
| 资产文件组成 | `AssetFileMembership` | 保留 |
| Profile 注册和 Schema 校验 | `data_asset_registry_service.py`、`registry.json` | 保留机制；上下文规则需随 ADR-005 调整 |
| 最小创建边界 | `create_data_asset` | 保留唯一 service 原则；当前无运行入口，且专业关系参数需重构 |
| 资产与成员文件组合授权 | `data_asset_access_service.py` | 保留 fail-closed 原则；当前无运行入口，必须补齐 Project 授权并移除 Dataset 权限依赖 |
| 文件校验、受控交付和审计能力 | 现有 DataFile 能力 | 按调用面逐项复用，不保留旧路径语义 |

### 5.2 必须重构后才能保留

- `datafile_access_service.py`：改为新仓唯一文件访问策略；
- `data_asset_access_service.py`：不再委托 Dataset 权限来源；
- `data_asset_service.py`：移除固定四类专业上下文写入；
- `data_asset_registry_service.py` 和 `registry.json`：上下文规则改由 ADR-005 批准结构表达；
- Data Overview 查询和详情：改为 DataAsset、AssetFileMembership 和新上下文；
- JBrowse、FASTA、AnnotationFeature 索引与 reference-name service：改为资产和成员文件解析；
- raw data、genome、transcriptome、external discovery/sequence service：移除 FileRelation 查询；
- token scope、外部文件 metadata 和 manifest：改为明确的新 API 契约；
- 旧前端 Data Overview、Accession 详情和相关文案：G5 前先移除对旧表的运行依赖；G7 再设计并实现新 DataAsset 用户流程。

### 5.3 迁移或旧系统专用，目标为删除或归档

以下能力不应继续扩展：

- `audit_dataset_migration_readiness`；
- `audit_dataset_dataasset_mapping_dry_run`；
- `audit_datafile_asset_mapping_readiness` 中只服务旧关系映射的部分；
- `import_dataset_manifest`；
- `import_dataset_accession_manifest`；
- `publish_external_datasets`；
- `validate_prjeb73710_relationships`；
- `backfill_assembly_from_genome_relations`；
- `migrate_placeholder_hierarchy`、`cleanup_placeholder_hierarchy` 及只服务旧层级的导入/生成命令；
- 依赖 Dataset 的 external dataset manifest service、view、URL 和 OpenAPI 定义；
- 仅验证旧 Dataset/FileRelation 行为的测试。

生产审计报告和历史 migration 继续保留为证据。删除活动命令不表示删除已经归档的 T0、T1、T4 报告。

### 5.4 暂不能决定删除的专业实体

以下模型的最终归属必须由 ADR-005 决定：

- Accession；
- Sample；
- Assembly；
- Annotation；
- `DataAssetAccession`；
- `DataAssetSample`；
- `DataAssetAssembly`；
- `DataAssetAnnotation`。

候选方向是把具备核心文件的 Assembly、Annotation 表达为 DataAsset，把 Sample、Subject、Experiment 表达为通用上下文，把 accession 表达为外部标识。但该方向目前只是 draft 设计输入，不能作为本次删除依据。

## 6. Management command 处理矩阵

当前命令不能按是否包含 `Dataset` 或 `FileRelation` 一次性删除，应分为：

| 分类 | 代表命令 | 处理方式 |
| --- | --- | --- |
| 历史审计与迁移准备 | `audit_dataset_*`、`audit_datafile_asset_mapping_readiness` | 归档证据后删除活动命令 |
| 旧 Dataset 导入发布 | `import_dataset_*`、`publish_external_datasets` | 删除，不在新仓保留兼容写入 |
| 旧层级修复与回填 | `backfill_*`、`migrate_placeholder_hierarchy`、`cleanup_placeholder_hierarchy`、`reconcile_assembly_annotation_context` | 删除或归档，不迁入新仓初始化 |
| 文件接收与扫描 | `scan_files`、`bind_manual_files`、`import_raw_data_manifest`、`import_data_batch` | 重新评审；只保留能够通过唯一新仓 service 创建 DataFile/DataAsset 的部分 |
| 索引与工具准备 | `build_fasta_indexes`、`build_annotation_feature_indexes`、`audit_public_fasta_indexes` | 改为从 AssetFileMembership 和 Profile 解析输入 |
| 外部接口审计 | `audit_external_api_readiness`、`audit_datafile_access` | 随新权限和新 API 契约重构 |
| 示例和特定数据命令 | `seed_ir64_demo_hierarchy`、`validate_prjeb73710_relationships` | 不进入通用新仓生产初始化 |

## 7. 正向 migration 方案边界

### 7.1 原则

- 不修改 `0001` 至 `0027` 的历史 migration；
- 新增正向 migration，使从零执行完整 migration 链后的最终 schema 不含旧活动表；
- 新仓空库不执行旧生产业务数据回填；
- model、service、API、前端和测试调用未切换前，不创建删除 migration；
- 专业实体和四张 DataAsset 上下文关系表的删除必须等待 ADR-005；
- 每个破坏性删除独立评审，不与 API、前端和权限重写混成一次提交。

### 7.2 候选顺序

1. ADR-005 批准替代关系、外部标识和权限边界；
2. 新增替代结构及约束的 migration；
3. 重构创建、访问、查询、JBrowse、索引和外部接口 service；
4. 删除或停用 Dataset/FileRelation 的写入命令、旧 API 路由和旧前端入口，使应用在没有旧表时仍能启动；本步骤不要求提前实现新前端；
5. 新增 migration，先移除 `DataFile.dataset` 外键；
6. 删除 `DatasetAccession`；
7. 删除 `FileRelation`；
8. 删除 `Dataset`；
9. 根据 ADR-005 的独立决定，另行处理四张 DataAsset 专业关系表和旧专业实体；
10. 执行 G5：从空开发数据库执行完整 migration 链，检查最终表清单、应用启动和旧路由不可用；
11. 执行 G6：通过唯一 service 验证最小后端创建和授权流程；
12. 执行 G7：设计并实现新的 DataAsset API、搜索和前端流程。

以上是删除依赖顺序，不是已批准的 migration 文件名或生产执行授权。

## 8. API 与前端切换边界

G4 不实施 API 和前端修改，但必须区分两个阶段：

- **G5 前的旧依赖清除**：删除或停用访问 Dataset/FileRelation 的旧 API、URL、serializer、前端入口和契约测试，使最终 schema 删除旧表后应用仍可启动；此阶段允许暂时没有对应的新页面；
- **G7 的新能力建设**：在 G6 最小后端流程通过后，再定义 DataAsset API、检索、manifest 和前端用户流程，不复活旧 Dataset 语义。

G7 至少需要处理：

- 资产列表、搜索、详情和文件成员接口；
- 资产 manifest 或受控文件选择接口；
- DataAsset 与 ContextEntity/ExternalIdentifier 的展示；
- Project 和资产权限在每个返回节点上的授权；
- Data Overview 的 Dataset 筛选和字段退役；
- Accession 页面的 Dataset 标签退役或按新外部标识/资产语义重新设计；
- JBrowse 能力由 Profile、文件角色和资产关系判断；
- OpenAPI、token scope、前端测试和后端契约测试同步更新。

旧 API 若需要短期保留，必须有明确版本、负责人和删除门槛；不得让旧 Dataset API 与新 DataAsset API 长期共同成为活动事实来源。

## 10. G4 收口结论

1. `DataAsset + AssetFileMembership + DataFile + Project + Profile` 是可继续验证的通用基础；
2. DataAsset 模型与最小 service 已存在，但没有测试以外的运行入口，不能描述为新仓业务链路已接通；
3. 当前实现仍存在实质性双体系：主要页面、权限、外部 API、JBrowse 和导入链仍以 Dataset/FileRelation 为事实来源；
4. Project 当前没有成员、角色或真实用户 owner 关系，尚不能承担新仓权限边界；
5. 不能直接删除 Dataset、FileRelation 或专业实体；首先必须批准 ADR-005 并建立替代关系和权限路径；
6. T4 和旧关系迁移命令不再扩展，待替代调用完成后删除；
7. 最终正向 migration 必须删除 `DataFile.dataset`、`DatasetAccession`、`FileRelation` 和 `Dataset`，但具体 migration 只能在调用面切换后创建；
8. Accession、Sample、Assembly、Annotation 及四张 DataAsset 显式关系表的最终处理尚未批准；
9. G5 前移除旧 API/前端运行依赖，G7 再建设新 API/前端，二者不能混为一次跨层重写；
